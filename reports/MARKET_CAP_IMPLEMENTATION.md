## 마스터 형식과 검증

`config/market_cap_area_master.csv`에는 다음 열을 사용합니다.

| 열 | 정의 |
|---|---|
| kapt_code / area_group_id | 기존 단지 식별자 / 단지 안에서 유일한 전용면적 그룹 |
| exclusive_area_sqm | 정확한 전용면적, 필수 |
| supply_area_sqm / type_name | 확인 가능한 공급면적 / 타입 설명, 선택 |
| households | 해당 전용면적 그룹의 양의 정수 세대수 |
| source / verified_at | 출처 URL 또는 문서·페이지 / 확인일 |
| valid_from / valid_to | 구성 적용 시작·종료일, 종료일 포함; 미확인 시 빈칸 |
| verification_status | `verified` 또는 `pending` |
| scope | `sale_apartment`, `rental_apartment`, `unknown` |
| notes | 원자료 대조와 한계 |

동일 전용면적의 A/B타입은 검수자가 세대수를 합쳐 한 행으로 기록합니다. 타입별 가격 차이는 구분할 수 없습니다. 공급면적을 매칭에 쓰지 않습니다. 소수점 차이를 검증할 원자료가 없으므로 기본 허용 오차는 **0㎡**이며, 임의의 84㎡대 묶음을 금지합니다. 실거래 전용면적 분포는 `observed_areas.csv`로 제공합니다. 이는 세대수 자료가 아닙니다.

중복 식별자·동일 전용면적의 적용 기간 중복, 음수/누락/소수 세대수, 잘못된 날짜, 출처 없는 verified 행을 검사합니다. 총세대수 합계가 맞지 않으면 비례 보정하지 않고 불완전 처리합니다. 현재 첫 버전은 임대·혼합 단지에서 매매 가능 세대 분모를 별도로 확정하지 않으므로 해당 단지는 범위 보완 상태로 남깁니다.

## 최종 산정 규칙

`config/market_cap.json`에서 규칙을 관리합니다. 가격 provider는 `src/market_cap.py`의 `TransactionMedian`으로 분리했습니다.

1. 평가월 말일까지의 최근 3개 달 거래를 합친 중위가격을 사용합니다. 기본 최소 표본은 3건입니다.
2. 부족하면 최근 6개 달, 다시 부족하면 최근 12개 달에서 최소 표본을 확인합니다. 각 창을 독립 조회하므로 거래를 중복 가산하지 않습니다.
3. 12개월 1~2건이면 소표본 D, 거래가 없으면 가격 결측입니다. 기본 랭킹은 전체 평형이 산정된 A·B이며 C·D는 선택 확장입니다.
4. 내부 단위는 원. 매매 원본 만원×10,000, 화면 억원÷100,000,000. 세대당 가치는 시가총액÷산정 세대수입니다.
5. 준공 전·준공일 미확인, 세대수 부족·합계 불일치·범위 미확인, 가격 누락은 전체 시가총액을 결측 처리합니다. 가격이 있는 평형의 합계는 부분 합계로만 남깁니다.
6. 1개월 가격은 별도 비교이며 기본 랭킹에 섞지 않습니다. 표본 수·부족 여부를 함께 표시합니다.
7. 동률은 공동 최소 순위(1,1,3), 표시 순서는 식별자로 고정합니다. 부산 전체 순위는 지역/검색 필터 이전에 계산합니다. 동일 규칙·조회 모드에서 전월/전년 비교 및 공통 단지 순위를 계산합니다.

초기 3건 기준은 통계적 신뢰구간이 아닙니다. 2/3/5건 민감도는 `sensitivity.csv`로 저장합니다. 현재 마스터가 없어 어느 임계값에서도 완전 산정 단지는 0개입니다. 실제 시가총액 변동성과 임계값의 경제적 영향은 세대수 보완 뒤 검증해야 합니다.

## 취소·중복·특이가격

취소 여부와 금액·계약일 정규화는 기존 `clean_trade`를 재사용합니다. 기존 분석에 영향을 주지 않는 `preserve_rows=True` 옵션을 추가했습니다. 기존 정제는 같은 날짜·층·면적·가격을 합치므로 이번 배치는 원본부터 읽습니다. 지역/월별 최신 snapshot 하나만 사용하고 원본 행 식별자를 붙여 같은 조건의 복수 행을 보존합니다. API는 개별 거래 고유 ID를 제공하지 않는 경우가 있으므로 동일 조건 행이 실제 복수 거래인지 중복 응답인지는 자동 확정하지 않습니다. 해당 행은 확인 플래그로 남깁니다.

취소 표시 거래는 제외합니다. 직거래, 사용 표본 중위가격의 0.5배 미만/2배 초과 가격, 동일 조건 복수 행은 조회용 플래그만 추가합니다. 가격 수준만으로 거래를 삭제하지 않습니다. 명시적인 거래 ID가 없는 취소 기록과 동일 조건의 정상 기록을 추측으로 상쇄하지 않습니다.

## 이력·갱신·배포

`data/processed/market_cap/YYYY-MM/실행해시/`에 평형 가격, 단지 시가총액, 사용 거래, 실행 메타데이터를 저장합니다. 입력 파일 내용·코드/규칙·마스터 해시로 실행 ID를 만듭니다. 동일 입력은 새 revision을 만들지 않습니다. 최초 저장 결과는 수정하지 않으며 manifest의 첫 revision과 마지막 revision을 각각 조회합니다. 기존 월의 새 입력에는 수정 사유가 필수입니다.

배치는 배타적 `.batch.lock`으로 동시 실행을 막고, 완성된 월별 폴더와 manifest를 원자적으로 게시합니다. 비정상 종료 뒤 잠금이 남으면 해당 PID의 실행이 종료됐는지 확인한 후 잠금 파일만 제거합니다. 일부 월까지 완료한 배치는 재실행으로 이어갈 수 있습니다. `--backfill`도 최초 산정 결과를 덮어쓰지 않습니다.

매월 작업 순서: 기존 수집/정제 명령으로 자료와 매핑 갱신 → 평형 마스터 검증 → 월간 배치 → `audit.json`/보완 목록/민감도 확인 → 기존 배포 절차로 산출물 반영. 데이터 수정은 영향을 받는 과거 월을 명시하거나 `--backfill --reason ...`으로 재산정합니다. 기존 스케줄러 자동 등록은 하지 않았습니다.

Windows 작업 스케줄러 등록 예시:

- 트리거: 매월 18일 06:00 (수집 완료 일정에 맞게 변경).
- 프로그램: 프로젝트 `.venv\Scripts\python.exe`의 절대 경로.
- 인수: `-m src.market_cap_batch --reason "월간 수집 갱신"`.
- 시작 위치: 프로젝트 루트의 절대 경로.
- 중복 실행: 새 인스턴스 시작 안 함. 실패 시 로그와 종료코드 확인.

앱 배포에는 `data/processed/market_cap/` 전체와 config 양식, 새 모듈을 포함합니다. `.gitignore` 예외를 추가했습니다. 원본 수집 파일과 K-apt parquet는 로컬 배치에서 필요하지만 공개 앱에는 필요하지 않습니다. 실제 배포/스케줄러 등록은 수행하지 않았습니다.
